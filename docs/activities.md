# 处理活动与监管检查

1. 在工作区登记数据资产，再到「处理活动」新增活动。填写处理目的、接收方或模型服务、处理地域、留存和训练条款。数据出境活动须填写接收方和目的地域，可补充拟采用的出境路径与保护措施。
2. 从活动详情发起监管检查，核对带入的资产和活动，再选择适用的规则。将实际核查对象、范围和通过标准写入「检查范围与标准」。同一活动可以按需要关联多项检查。
3. 在检查详情登记证据的来源系统、原始记录编号、观察时间和脱敏摘要，再提交独立复核。源端原始材料、业务数据和凭据保留在源系统。
4. 收到整改要求后，在源系统执行整改并登记变更记录。使用整改后新取得的证据登记复测，再提交独立复核。经办人和复核人使用各自账号，检查详情可导出包含关联活动、证据和操作时间线的 JSON。

下表给出三类活动的候选规则和验收示例。由工作区人员按实际处理目的、数据流向和适用要求选定规则与通过标准。

| 场景与候选规则 | 可登记的证据引用 | 整改复测通过示例 |
| --- | --- | --- |
| 对外共享或委托 · T01 | 共享审批或委托协议编号、批准的数据范围、接收方实际权限记录。 [《网络数据安全管理条例》第 12 条](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm) | 以指定接收方重新验证。已批准范围仍可访问，整改要求移除的权限在约定访问路径上无法再使用。 |
| 数据出境 · T03 | 数据流向图版本、实际发送或远程访问的审计记录、目的地域和接收方配置、出境路径评审及其依据。 [《促进和规范数据跨境流动规定》](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm) | 核对变更后的配置与实际运行记录，确认目的地域、接收方和传输路径符合批准范围。若整改涉及拦截，重跑未获批准的测试路径并留存拒绝记录。 |
| AI 使用 · X01 | 模型服务与地域配置、供应商留存及训练条款版本、网关策略版本和脱敏测试编号。 [《生成式人工智能服务管理暂行办法》第 2 条](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm) | 用合成数据重跑同一用例，确认允许的请求进入批准模型，受限制数据按设定脱敏或阻断。涉及留存或训练的整改，复核实际启用的配置和条款。 |

Django 历史活动和检查按原资产关联分别导入，保留原记录。旧版检查没有处理活动关联字段。需要按活动复查时，可打开已导入活动发起新的关联检查，并在证据中引用历史记录。

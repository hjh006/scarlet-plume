# Agent 任务、委托与连续数据约束

任务将一次多步 Agent 工作绑定到实际工作区、应用、主体和应用凭证。任务 ID 只是选择符，不能自报身份、用途、权限、来源或敏感类别。任务范围与当前网关配置、安全目录和源授权取交集，不能替代工具独立批准。

## 能力与边界

| 控制 | 实际行为 |
| --- | --- |
| 身份 | 初始 `credentialId` 保留在不可变任务授权中；当前执行凭据由独立租约记录。子任务可绑定同应用、同主体下另一枚有效凭据；逐次复核全部祖先的当前租约和原任务范围，不提供跨租户或跨主体的任意授权委托。 |
| 用途与范围 | 用途由受授权管理员创建任务时确定；限制模型、直接读取的文档、类别和每个工具的精确动作/目标。模型和工具仍经过原有目录规则。 |
| 多步预算 | PostgreSQL 原子计步，所有后代共享祖先剩余步数及预算。换节点、换凭证或继续委托不会重置额度。缓存、RAG、工具也计步。 |
| 备用模型 | 一次逻辑模型步骤可以包含独立授权的备用尝试。逻辑步数不重复计算，每次真实提供方尝试独立预占并约束全部祖先预算；未知费用不自动释放。 |
| 连续数据限制 | 成功读取/处理后的实际来源绑定与类别通过受验证的运行回执保留。后续省略文档 ID 不能移除敏感类别、用途、留存、禁训练或源撤权约束。 |
| 最小权限委托 | 子模型/工具/直接文档读取/类别、期限、预算、步数及剩余委托深度不能扩大；工具动作/目标逐项取子集。继承的敏感类别需被子任务明确允许。 |
| 历史上下文 | 子任务可以缩小直接读取文档范围，即使父任务已有来源历史。历史绑定仅用于私有复核和继续约束数据，不能据此向子任务自动返回或注入原文。 |
| 终止 | `cancelled` 或 `completed` 停止该任务及后代，失效相关待/已批准动作；不能恢复为 active。默认每秒巡检在途任务，并在执行、缓存、来源/输出及 SSE 回放时复核。已发生副作用和未知费用保留事实，不宣称已回滚。 |

正在执行的权限也受应用/主体租约、目录发布、源 ACL/正文变化及目的端约定到期影响。巡检间隔不构成商业 SLA，依赖控制面响应；控制面或审计故障时拒绝或抑制输出。

## 创建与使用

在“AI 网关与企业治理 → Agent 任务与委托”中选择当前已批准应用、凭证、模型、工具、资料、类别及用途。使用当前 `catalogDigest`；目录变化后旧任务不能被当作新的执行许可。任务 scope 不原地扩大，变更授权应创建新任务或受限委托。

- 初始有效期必须在数据库当前时刻之后且不超过 7 天。
- 步数为 1—1,000,000；预算为 0—9,000,000,000,000,000 USD 微美元。
- 最多 4 层委托，剩余深度每层收缩；子任务上限不能超过祖先当时的剩余量。祖先之后的其他调用仍可耗尽共同余额。
- 模型/工具各最多 200 项；文档/类别各最多 64 项。每个允许工具必须有一个非空 `toolScopes` 项，动作/目标各最多 200 项，目标精确匹配、最长 2048 字符，不接受通配符。HTTP 请求大小限制仍另外生效。
- 工具参数继续采用目录中的精确允许值与必填参数；高影响操作仍需独立批准，批准摘要包含任务 ID，不能跨任务复用。

调用方式：

```text
POST /v1/execute
{"taskId":"<actual task ID>", ...the existing runtime request...}

POST /v1/chat/completions
X-Scarlet-Task-Id: <actual task ID>

POST /mcp
X-Scarlet-Task-Id: <actual task ID>
```

JSON body 与 header 同时选择任务时必须一致，不能重复或覆盖。MCP 发现/工具列表也按任务范围过滤精确动作与目标；发现调用不冒充工具执行或消费业务步骤。客户端不能传入私有任务 grant、taint、用途声明或来源证据来扩大授权。

安全目录的 `Application.requireTask` 与控制面 `GatewayApplication.requireTask` 都可要求任务；任一实际采用边界要求任务时不得绕过。生产节点先查询当前控制面要求，再做实际资料读取与检查。生产升级应先部署控制面和迁移，再采用网关 v4。旧节点的 healthy 状态不等于具备任务/来源能力。

## 控制面接口

| 接口 | 用途 |
| --- | --- |
| `GET/POST .../ai-gateway/tasks` | 当前工作区分页查询或创建任务/委托 |
| `GET .../tasks/{id}` | 任务当前状态、来源元数据与最近步骤，附 `stepsTruncated` 预览标记 |
| `GET .../tasks/{id}/steps?before=...&limit=50` | 完整步骤历史的倒序 keyset 分页，返回 `items/hasMore/nextCursor` |
| `GET .../tasks/{id}/credential-status` | 当前执行凭据与全部祖先的授权阻断诊断；只读 |
| `GET .../tasks/{id}/credential-lease` | 当前完整执行租约链、原授权凭据、CAS、链摘要及提出条件 |
| `GET .../tasks/{id}/credential-lease/history` | 续期与换绑事实的倒序分页，`before/limit` |
| `GET/POST .../tasks/{id}/credential-bindings` | 分页读取或提出受控换绑申请 |
| `GET .../credential-bindings/{proposal}` | 单条申请的冻结身份、当前可复核状态与阻断事实 |
| `GET .../credential-bindings/by-operation/{operationId}` | 提交结果不确定时按稳定操作标识核对 |
| `POST .../credential-bindings/{proposal}/review` | 另一位 Owner/Reviewer 独立复核；批准与应用同一事务完成 |
| `GET/POST .../tasks/{id}/credential-renewal` | 持新的工作负载短期 Bearer 令牌、严格无 Cookie 的机器预检与同身份续期 |
| `POST .../tasks/{id}/credential-renewal/complete-step` | 新有效同身份凭据提交精确历史终态回执，完成或封存旧步骤；不授予新执行许可 |
| `POST .../tasks/{id}/status` | `expectedRevision` + `status` + `reason`，冲突不覆盖新状态 |
| `POST /api/v1/internal/ai-gateway/task/check` | 已认证工作区节点查询当前范围、所有祖先和数据约束 |
| `POST .../task/steps/admit` | 原子绑定逻辑步骤、防跨节点重放、检查祖先步数 |
| `POST .../task/steps/complete` | 绑定实际持久运行回执，保留来源和类别；不接受客户端空口声明 |

任务列表与步骤默认 100 条，租约历史与换绑申请列表默认 50 条；上述列表最大 200 条，显式空值、非法或超限页长返回 400。任务列表将 `nextCursor` 作为下一页 `after`；步骤接口将 `nextCursor` 原样作为 `before`。步骤游标绑定工作区和任务，跨任务使用返回 400；没有更多数据时 `hasMore=false` 且游标为空。详情中的步骤仅为预览，完整历史需使用步骤分页接口。控制台配置预览不能解析/占用真实任务，缺少可信上下文时拒绝；发布门禁只构造显式标注的合成上下文测试纯引擎契约，不创建真实任务或证明客户执行成功。

## 资料与目的端

实际正文读取、私网源契约、用途/留存/禁训练配置见[资料源连接器](ai-security-source-connector.md)。模型引用资料时注入真实核验正文；原文和最终外发 JSON 都受预算与检查限制，报价使用实际构建的外发字节，媒体归一化与来源封装不会被漏计。

任何当前或历史来源带有 `usePolicy` 时，该派生请求不使用响应缓存。其他文本缓存按任务 ID、用途、范围、实际来源和类别隔离；命中仍消费步骤、执行 RPM/TPM 及当前授权检查，不产生新的提供方报价。审计只记录范围、摘要、阶段、类别与占额元数据，不记录资料正文或模型输入输出。

`completed` 代表处理和检查终态，不证明客户端完整收到结果；外部工具副作用仍需业务侧核对。数据库高可用、独立不可变留存、真实源/企业身份适配及客户业务验收依赖对应部署环境。

## 执行凭据租约、安全续期与受控换绑

Owner 可通过[静态 JWKS 工作负载绑定](ai-gateway-enterprise.md#工作负载-jwt-与短期凭据)签发最长300秒的应用凭据。任务的初始 `credentialId`、范围摘要和原有效期保持不变；执行采用独立租约的当前凭据。每次变化递增租约修订，并形成 `scarlet-task-lease-v1` 全祖先链摘要。该摘要同时绑定根任务至当前任务的原范围与当前凭据，独立于业务请求摘要。

兼容节点必须理解租约协议：首轮检查可读取当前摘要，之后的准入、提供方尝试、缓存、工具、流式回放及内容释放固定核对同一摘要。旧节点或遗漏摘要的节点不能以旧接口语义继续执行任务。已有发布目录与历史回执不回填当前租约；升级控制面和迁移后，同步更新实际采用任务的执行节点。

### 机器同身份续期

机器持已经兑换的新有效 `sgw_` 令牌调用同一任务的 `GET /credential-renewal`。请求不能带Cookie；新令牌必须匹配任务应用、主体及链内实际工作负载身份。预检只返回续期所需的CAS、标识、期限及信任修订，不返回任务正文、令牌、JWT或私钥。

随后 `POST /credential-renewal`，提交：

- 稳定且唯一的 `operationId`，以及预检的 `expectedLeaseChainDigest`。
- `expectedChain`：按根至叶的完整路径，逐层包含 `taskId/taskRevision/leaseRevision/credentialId`。凭据编号取当前 `node.lease.credentialId`，不能取初始授权编号。
- `replaceTaskIds`：本次需要续期的路径内任务，必须包含URL选定的当前任务。目标凭据由Bearer身份推导，客户端不能指定任意目标凭据。

源凭据可以自然到期；其真实签发修订必须已记录，且签发者、audience、subject、绑定和修订与当前可信事实一致。已明确撤销、信任变化、历史签发未知或无法证明身份连续时拒绝续期。新的短期凭据还需比被替换的凭据更新并具有更晚的到期时间。不同身份的祖先需要先由相应身份续期祖先任务，再重新预检当前任务；不能只替换叶任务越过失效祖先。

相同操作标识和相同载荷的重复提交返回既有变化事实；不同载荷不能复用标识。保存原操作标识与精确载荷后再提交，网络结果不确定时先查询或按原载荷幂等重试，不能生成新操作标识假定上次未执行。

### 控制面受控换绑

Owner/Operator提出申请，另一位Owner/Reviewer独立复核。申请冻结完整祖先CAS、链摘要、源与目标凭据元数据，以及工作负载issuer、audience、subject和签发修订；不包含秘密。批准时在锁内重新核对当前事实，并原子应用；冻结快照不能替代当前有效性检查。

- 静态源在仍有效时可以轮换到同应用的静态凭据，或迁移到当前可信工作负载凭据。
- 工作负载源可以受控迁移到另一可信工作负载身份；不能降级为静态凭据。历史签发未知、已撤销或未知停用的源不能通过换绑恢复。
- 应用与主体必须一致。换绑不能扩大模型、工具、文档、用途、数据类别或源权限，不能延长任务及祖先期限。
- 默认申请窗口至多15分钟，并缩短至当前源、祖先、所选目标短期凭据及相关任务的最早期限。过期、旧CAS、自审、目录或身份变化均不能应用。
- 相同 `operationId` 和规范化载荷幂等返回原申请，载荷不同返回冲突。复核使用 `expectedRevision/decision/note`；重复或过时复核返回冲突，随后读取该申请核对实际状态。

切换使相关旧租约审批失效，旧审批不会被补填新摘要；新的高影响调用仍需重新独立提出和复核。计划切换成功后，退役旧凭据的后续撤销只影响仍使用它的任务。若要停止当前任务及后代，应停止任务，或撤销当前执行凭据及其信任绑定。源撤销先于切换完成时，切换必须失败；不能用换绑绕过已经生效的撤销。

计划轮换工作负载公钥时，先建立新的可信绑定并签发目标凭据，经受控换绑确认后再撤销旧绑定。直接修改旧绑定会使其已签发凭据失效，不能将该变化当作自然到期自动续期。

### 在途执行、预算与历史完成

续期与换绑不重置步骤、累计费用、未决预留、资料来源或已观察类别。控制面换绑会拒绝受影响子树中尚未核对的准入步骤与未决预留，零费用步骤也不能跳过检查；系统不会自动退还未知费用。

同身份续期可更新租约，但旧epoch仍有未完成步骤时，新epoch不能跳过旧步骤开始新的执行。受信任执行点可持当前同身份租约，通过机器 `credential-renewal/complete-step` 入口提交已经持久化、精确匹配的旧epoch终态审计及原来源证据。应用、主体、工作区与目录由服务端派生；客户端只能提交当前协议与链摘要、原步骤、实际终态审计和来源。成功步骤仍为 `completed`；真实失败或已拒绝步骤封存为 `closed`，不宣称成功或副作用回滚。中间任一变化为换绑时不能采用这条恢复路径。结算仍按原预留和过去执行事实记账，不能把历史落账当作新执行许可。缺少真实终态或费用未知时保留阻断，需要原执行来源继续核对，不能用客户端声明 `not_attempted` 释放占额或伪造成功。

业务约束阻断时接口给出 `code/blockers/recovery`，区分CAS冲突、身份不连续、凭据不可用、未决在途及终态证据缺口；普通认证或参数错误可能仅返回 `error`，调用方应兼容。控制台保留草稿与操作标识，显示具体任务、步骤和预留引用，不以旧数据或零值代替未知事实。

# 场景办理的数据自动获取

概览继续作为平台默认入口。进入具体场景后，“已接入来源与采集数据”先显示工作区的来源状态；选择已有资产或处理活动后，读取该范围的来源事实。选择范围不会新建业务记录。

## 已接通的获取方式

| 来源 | 可自动获取 | 使用范围 |
| --- | --- | --- |
| 托管 PostgreSQL | 已有结构识别结果、源内分析覆盖 | 对应资产、最新成功且目标匹配的检查结果 |
| MySQL / MariaDB / MongoDB / OpenMetadata 多源发现 | 已采集的结构、识别类型、可得权限、采集覆盖与限制 | 对应目录资产；校验来源修订、最近采集、有效期、启停及创建人权限 |
| 应用配置 API | 应用、供应商、模型、配置地域、留存、训练使用、服务对象声明、知识库、工具及数据类别声明 | 来源令牌绑定的工作区与资产；最新成功且未过期的快照 |
| 处理活动、分类与 CMDB | 复用已有登记；CMDB 的来源声明、人工确认和冲突分开保留 | 对应活动或资产，显示为“已登记” |
| API 运行时与安全运营 | 来源连接、最近接收状态与时间 | 来源状态用于接入排查；具体事件和控制证据仍在对应专业工具中核对 |

“已获取”表示来源返回了数据。应用/API 设置属于配置声明，需要结合实际处理情况和合同核对。去重主体数量、合法性依据、法定例外、关基身份等业务与法律条件继续保留待确认项。已有托管 PG 检查未记录采集时的配置修订号，也未增加年龄时效校验，其失效能力与新版多源目录及应用采集不同。

## 在评估中复用分类上下文

个人信息影响评估、数据出境评估和业务变更重评的内置模板 v2 新增可选的“已确认分类与业务目录上下文”文本题，对应事实键 `classification_context`。该题复用同一资产可核验的人工分类确认、采用标准及条款引用、业务目录与发布记录摘要；未确认、存在冲突或失效的结果继续显示待核实，不作为已确认上下文自动带入。

这是一项组织治理辅助题，不新增法定材料要求。已有的处理范围与接收角色、去重主体数量、适用性、风险、出境路径及证据题保持原有要求，分类上下文不代替这些答复。新建评估仍固定实际选择的处理活动和已发布模板版本；已采用 v1 的评估保留原题和历史答复。AI 使用模板继续采用已有 v2 配置摘要题，不因本次分类上下文迁移改变。

## 按场景继续办理

个人信息保护、国内合规与迎检、数据跨境合规的具体任务共用所选资产或处理活动。分类台账和详情提供三个场景入口；资产、活动及办理任务通过 URL 保留，切换工作区时清除原范围。深链接中的记录不在列表首屏时按真实 ID 读取，不按名称猜测。

材料清单区分“已自动带入”“需核实”“待补充”和有据“不适用”，显示采用记录及补充入口。确认分类可复用数据属性、内部敏感级别、法定类别登记值、标准与条款、业务目录及发布版本；自动识别与 AI 建议保留为候选。目录、来源或规则失效时提示重新核对；新的有效人工确认可带入，旧发布版本另行标识变化。

已有用途、接收方、地域、保存安排、传输路径和措施按处理活动带入。缺失项进入原活动表单、同范围评估或检查中补充，仍由用户确认保存。检查与评估列表支持 `assetId`/`activityId` 的实际服务端过滤；不把工作区其他记录当作该范围的办理材料。已建立的专项评估可继续办理，避免重复创建。

法律条件、去重主体数量、适用例外及外部办理结果未取得可靠事实时保持待核实；已有答复或证据引用可提示继续核对，不据此自动给出监管结论。不适用仅采用同一活动、当前事实相符、独立批准且具有明确理由和真实范围证据的评估记录。

## 接入应用 API

1. 工作区负责人在场景页选择已有资产或处理活动，填写来源名称并创建来源。页面仅在创建时展示一次来源令牌；数据库保存摘要。
2. 在客户侧配置获准的只读 API 和认证凭据。该 API 或客户侧适配层须返回下述约定 JSON，并将资产标识映射到平台实际 `assetId`。页面会显示此来源允许的资产 ID。
3. 启动客户侧 `scarlet-application-agent`。它定期 GET 配置快照，仅将允许字段上报赤翎；应用 API 的认证凭据留在客户侧。
4. 在场景页刷新数据，核对来源、观察时间、覆盖范围与缺口。选择对应活动创建 AI 评估时，v2 内置模板自动采用可用的配置摘要。摘要中的长值标明节选，完整值保留在来源事实中。

客户侧运行环境变量：

```text
SCARLET_URL=<客户侧可访问的赤翎 HTTPS origin>
SCARLET_APPLICATION_TOKEN=<来源创建时的一次性令牌>
SCARLET_APPLICATION_API_URL=<获准的只读 HTTPS 快照地址>
SCARLET_APPLICATION_API_TOKEN=<可选，应用 API 的 Bearer 凭据>
```

快照地址不能带用户信息、查询参数或片段。使用 Go 源码运行时，在 `backend` 目录执行：

```sh
go run ./cmd/application-agent -interval 1m
```

发布镜像中包含 `/usr/local/bin/scarlet-application-agent`，支持相同参数。`-once` 执行一次；计划间隔至少 30 秒。显式的 `-allow-insecure-loopback` 仅用于字面回环 IP 的本地合成样例。生产连接校验证书和主机名。

获准 API 返回 `Content-Type: application/json`：

```json
{
  "items": [
    {
      "assetId": 41,
      "facts": {
        "application_name": "客服助手",
        "application_vendor": "配置中的供应商",
        "application_model": "配置中的模型",
        "application_region": "配置地域",
        "application_retention": "30 days configured",
        "application_training_use": "disabled"
      }
    }
  ]
}
```

`41` 是格式示例，必须替换为获准资产 ID。其余可选字段为 `application_service_audience`、`application_knowledge_bases`、`application_tools`、`application_data_categories`。未知字段省略，每个资产至少一个非空事实；每次最多 50 个不重复资产，字段值最多 1,000 个 Unicode 字符。适配层应只输出配置描述，避免原始记录、提示词和凭据。

通用连接器提供约定快照采集。具体厂商原生 API 需要对应的字段映射或适配；本轮验收使用独立合成 API，未连接客户实际应用凭据。采集器细节与样例见 [命令说明](../backend/cmd/application-agent/README.md)。

## 失效与历史保留

- 默认配置有效期 60 分钟；来源管理 API 可设为 5 至 43,200 分钟。失败上报、最新快照缺失资产或字段、超时效及来源撤销后，旧配置不再作为当前可用事实。
- 同一事实存在相互矛盾的有效来源时，保留各项声明并标记待核实，禁止自动选择其中一项。相同批次重试不会刷新采集时点或覆盖更晚的快照。
- 来源创建人失去工作区负责人权限时，令牌上报与当前事实采用停止。撤销是永久停用该令牌的操作。
- 新建评估读取当前事实；已有评估按既有刷新机制提示变化，已采用答复和历史报告继续保留其来源快照。AI 模板 v1 保持不变；v2 增加可选配置摘要，原供应商条款及适用义务核对题继续独立填写。

## 接口

| 接口 | 权限与作用 |
| --- | --- |
| `GET /api/v1/workspaces/{slug}/scenario-data` | 工作区成员；可选 `assetId`、`activityId`、`scenario`、`task`，返回对应分类快照、范围事实、逐项材料状态、来源状态与缺口 |
| `GET /api/v1/workspaces/{slug}/application-sources` | 工作区成员；读取来源列表，不返回令牌 |
| `POST /api/v1/workspaces/{slug}/application-sources` | 负责人；提交 `name`、`assetIds`、`maxAgeMinutes`，返回一次性令牌 |
| `DELETE /api/v1/workspaces/{slug}/application-sources/{id}` | 负责人；撤销来源令牌 |
| `POST /api/v1/application-agent/observations` | 来源 Bearer 令牌；采集器提交带 `batchId`、`observedAt`、`status`、`items` 的受限快照 |

来源令牌只能向已绑定资产上报配置，不能用作用户会话或读取其他工作区。采集器关闭代理和跳转，GET 与上报均有 10 秒时限及 512 KiB 大小限制；日志省略来源响应、地址与凭据。

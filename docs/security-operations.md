# 安全运营与受控处置

控制台“运营与处置”位于`#/{workspace}/operations`。平台汇总已接入来源的安全信号、责任团队、风险与处置状态，并将其关联到现有检查、证据、整改、来源复测和独立复核。平台证据保存受控引用与脱敏摘要；附件正文由客户已有系统保管。原始日志、源系统凭据和业务正文留在客户侧。

## 来源与事件

工作区Owner可创建两类来源：

| 来源 | 用途与边界 |
| --- | --- |
| 安全事件集成 `security_events` | 接收规范化事件，或由客户侧`scarlet-event-bridge`投影Wazuh告警。仅保存事件标识、时间、类别、规则、等级、已核定资产/API范围、计数及窗口。 |
| PostgreSQL权限执行器 `postgres_control` | 绑定一个现有托管PostgreSQL采集任务。平台从当前有效采集推导主机、数据库、schema及表；执行器在客户侧持有独立数据库凭据。 |

来源令牌仅创建时显示，按用途绑定，撤销后不能继续领取或提交。浏览器操作仍要求成员关系、角色和同源校验；令牌接口按绑定来源确定工作区，不能用提交字段切换租户。

安全事件入口为`POST /api/v1/operations/security-events`，使用`Authorization: Bearer`。同来源、同`eventId`、同内容幂等重放；同标识异内容冲突。字段和大小均受限制，不接收完整日志或任意扩展对象。接入时明确：

- `observed`表示来源报告发现，计数大于零；`cleared`表示同来源后续范围未再检出，计数为零。
- 类别、服务、方法、规范化路由、资产与规则共同限定归并范围。其他资产、来源或规则的消除结果不能代替本项复测。
- 平台保存来源声明，不把“疑似泄露”“恶意活动”等事件类别独立认定为事实已成立。

“API主动验证”采用同一安全事件来源，但另有受限计划、独立审批和客户侧测试清单，见[主动验证说明](api-validation.md)。认证状态、敏感响应及请求模式的被动统计来自[运行时观测](runtime-security.md)，与主动验证分别保留依据。

## Wazuh与规范化事件桥接

客户侧程序`backend/cmd/event-bridge`支持`normalized`和`wazuh`输入。`SCARLET_OPERATIONS_TOKEN`由客户侧环境提供；平台地址通过`-url`指定。Wazuh Integrator调用时用`-file`读取授权告警文件，例如在客户环境运行：

```sh
scarlet-event-bridge -url 'https://scarlet.example' -format wazuh -file /path/to/approved-alert.json
```

规范化事件可从标准输入读取：

```sh
scarlet-event-bridge -url 'https://scarlet.example' -format normalized < approved-event.json
```

示例地址和路径需要替换为实际授权配置，令牌不写进命令。桥接只投影允许字段，舍弃Wazuh的`full_log`、任意`data`、主机/agent身份及自由文本描述；有限重试使用同一事件标识。生产连接验证TLS并拒绝重定向；本地开发模式另需显式开启。

已使用真实Wazuh4.14.10 manager完成固定合成导出接口的原生采集、解码、规则、Integrator与持久投影联调，并跑通实际200风险、断连未知不清除、403修复、源端新复测和独立复核。规则映射保留原告警ID及实际测量时间，不根据任意文案猜测修复。部署、映射、重试和范围见[Wazuh本地联调](wazuh-live.md)，两源联合结果见[验收记录](acceptance-live-integrations-2026-11-11.md)。其他SIEM、安全设备和云服务可在客户侧转成规范化事件；每种产品的实际版本、授权、输出字段和重试语义仍应独立验收。

## 从信号到独立复核

1. 来源正信号生成或更新对应G03检查，固定来源、资产、规则及范围，记录统计口径和证据引用。
2. 经办人核对原因、责任和期限，登记实际整改。运行时风险还可记录等级、团队和研判理由。
3. 取得整改后的新鲜来源复测。外部事件须由相同授权来源报告匹配范围的`cleared`；被动策略按其采用窗口与可观察分母复测；主动验证重新执行已批准计划。手工填写“已修复”不能替代这些来源事实。
4. 提交独立复核。创建人、提交人和证据贡献者回避；条件或来源失效不能沿用旧清除结果。已验证后出现更新的正信号进入新周期。

目录自动分类使用G02，采用标准、规则、人工分类版本和来源正向统计的约束见[发现与目录](discovery.md)。这些检查可以与本页处置相关联，但执行成功本身不产生“已验证”状态。

## 已审批的实际处置

Owner/Operator可提出限定目标、原因和有效期的处置申请。独立Owner/Reviewer审批；申请人和关联证据贡献者不能审批自己参与的动作。目标或范围不是执行器自行扩展的配置，采用修订与来源范围不一致时拒绝执行或回执。

| 类型 | 实际动作 | 回滚与完成条件 |
| --- | --- | --- |
| 临时阻断API `block_api` | 仅对未撤销独立代理来源中已观察的HTTP方法/规范化路由下发规则。客户侧`scarlet-runtime-agent`须显式启用`-controls`，命中时返回固定403，不将请求送往上游。 | 可请求回滚；代理依据有效期停止应用阻断，解除和执行回执分别留档。仅覆盖经过该代理的流量。 |
| 撤销表级SELECT `revoke_select` | 客户侧`scarlet-control-agent`对已确认目标角色执行带引用标识符的`REVOKE SELECT ... RESTRICT`。目标来自绑定托管PG任务的最新有效采集，只接受明确、非grantable的直接表级SELECT。 | 保存原始直接授权与耐久执行日记；回执重试不重复改权限。回滚只恢复该动作此前实际存在的直接SELECT，不能凭空增加原本不存在的权限。 |

权限动作**不是所有有效访问路径的撤权**。角色继承、所有者/超级用户能力、列级授权、其他角色或其他访问路径需要另行核验；不会通过`CASCADE`批量清除依赖，也不支持任意SQL、任意数据库厂商或通用权限重构。源端直接ACL变化、对象变化或超出授权范围会保留失败/范围变化结果。数据库执行账号和连接串留在客户环境，生产连接使用验证证书和主机名的TLS。

有效期、回滚申请、来源执行和平台回执是不同阶段。PostgreSQL回滚需要执行器在线、数据库可达且账号有权；执行器离线时，平台记录的到期不能替代真实权限恢复。运行时代理则对本地规则检查到期时间。界面区分待审批、待执行、来源执行成功/失败、待回滚和来源已回滚。

`applied`只表示来源报告完成动作。与检查关联的PG撤权还要求执行后的新鲜同目标采集确认直接SELECT已消失，再按整改时序提交独立复核；旧采集、失败采集、已变化来源或仅有回执均不足以通过。实际业务是否仍可访问还须按其真实权限路径验证。

## 客户侧执行器与本地开发

代理沿用已有运行时连接、路由清单、令牌和TLS配置，增加`-controls`才领取处置；未开启时继续作为观测代理。PostgreSQL执行器使用`SCARLET_OPERATIONS_TOKEN`与`SCARLET_CONTROL_PG_DSN`，通过`-url`指定平台，`-journal`指定需持久化的执行日记。容器卷与执行身份由部署者明确配置，不将运行日记或凭据提交到仓库。

根目录提供可选`compose.controls.yaml`；应与当前本地基础、样例及运行时覆盖文件一并加载，先迁移再启动新版服务。具体来源令牌、绑定任务和本地启动步骤以实际配置为准，不能直接把任意已有生产任务当作演示目标。基础入口见[README](../README.md#本机-docker)，多源持续发现侧车见[发现说明](discovery.md#本地docker持续采集)。

## 统计和报告口径

运营概览显示来源配置、来源事件、未完成检查、处置阶段、逾期风险、责任团队及最近30天趋势。来源数包括非撤销自动任务/运行时/运营来源和全部发现配置（包含暂停），不是物理系统去重数或实时在线率；来源计数、事件窗口和检查状态分别说明。首页只预览最近6项来源，不把预览条数当作总数。

合规报告在同一数据库快照中冻结所列检查关联的处置、审批与回滚事件、每项检查最新安全信号，以及运行时发现采用的策略/窗口/分母。目录评估和专项评估引用独立列示。HTML对动态文字转义，JSON保留来源与证据引用。来源回执与独立复核结论分开呈现。

## 验证范围

- 真实PostgreSQL18/SCRAM回归：租户/角色/来源隔离、事件幂等、整改后新鲜消除、旧清除与手工替代拒绝、独立审批、范围改变和TTL流程。
- 真实PG执行器回归：带引号的角色/对象、直接SELECT撤销、精确恢复、耐久回执重试不重复SQL。
- 代理回归：实际请求保持、受控403及到期/回滚解除；源端正文检查预算不能产生错误的完整负证据。
- 报告回归：策略后续编辑不改写旧发现采用的策略；目录、处置和活动引用冻结，动态内容不能变为可执行HTML。

测试入口包括`backend/internal/store/security_operations_test.go`、`control_actions_test.go`、`runtime_detection_test.go`、`backend/cmd/control-agent/main_test.go`及`backend/internal/httpapi/security_operations_test.go`。持久化测试使用独立数据库，按包串行运行`go test -race -p 1 ./...`；合成来源协议验收不替代客户安全设备和生产处置演练。

# 专项评估

赤翎以处理活动为范围，提供个人信息保护影响评估（PIA）、数据出境、AI 使用、业务变更四类版本化评估。每次评估固定采用的模板、活动快照和事实，复用已有资产分类、检查、来源证据与整改复核状态。

## 内置题库与依据

内置4个模板、27题，支持单选、多选、文本、数字、证据引用。每题保存适用条件、依据条款及公开链接、取证要求、验收标准，以及“依条件适用的法定义务”或“组织治理建议”标识。

| 模板 | 核验内容 | 公开依据 |
| --- | --- | --- |
| PIA | 触发条件、目的与必要性、处理范围、主体规模口径、权益影响、措施有效性、事前记录及保留 | 《个人信息保护法》第55—56条；相关处理规则按具体活动适用。[原文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm) |
| 数据出境 | 实际出境范围、接收方、关基身份、重要数据、普通/敏感个人信息主体数量及例外，路径与影响评估证据 | 《促进和规范数据跨境流动规定》第2—10条及《个人信息保护法》第38、55—56条。[跨境规定](https://www.cac.gov.cn/2024-03/22/c_1712776611775634.htm) |
| AI 使用 | 是否属于公众服务、输入和训练数据来源、供应商处理安排、个保影响评估触发条件、输入与工具权限控制 | 《生成式人工智能服务管理暂行办法》第2、7、11条，以及《个人信息保护法》第55—56条；供应商和权限治理题单独标为治理建议。[暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm) |
| 业务变更 | 变更前后范围、目的/方式/类型/接收方/地域、相关告知同意与评估条件、批准、回退和复测 | 《个人信息保护法》第14、17、55—56条。统一变更审批与复测作为组织治理建议，不声明所有变更都有相同法定审批义务。[原文](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm) |

PIA 的法定保存要求与适用触发条件分别核验；普通内部 AI 应用不因“使用 AI”自动适用面向境内公众服务的全部义务。出境路径不会由一张表的行数或有限格式样本代替自然人去重统计、关基身份、法定类别和例外事实。题库为明确版本的实施起点，新的监管要求需要核验官方文本后发布新版本；本模块不宣称覆盖所有行业专项要求或所有 AI 内容标识场景。

## 自动事实与人工核验

创建时自动读取活动目的、接收方、地域、保留和保护措施；资产已登记分类、业务等级、法定类别及分类修订；存在当前有效 PostgreSQL 深采集时，读取敏感候选类型及观察覆盖。PostgreSQL 事实要求最新任务运行成功、目标地址与当前任务一致；采集失败、已撤销、目标改变或最新扫描没有该资产时保留未知。

模板的文本题可以绑定事实键；创建时自动填入已有事实并记录来源引用。AI 和出境专项可由已登记活动类型自动判定是否符合该评估范围，并预填范围答复。这是登记事实的范围匹配；具体法定义务由题目的条件和证据继续核验。未知处理依据、主体数量、关基身份、公众服务范围、自动化决策用途和例外条件保留 `unknown`，需要有依据的业务答复。

缺口包括未答必填题、未知选项、缺少引用证据；风险包括活动范围与不适用答复冲突，以及关联整改检查尚未独立复核。文本内容的实质充分性由独立复核人员判断，系统完整性校验不会代替法律评估。

## 模板与分工

Owner 可以新建、复制、编辑草稿、发布及停用本工作区版本。发布复用已有 `check_templates` / `check_template_items`，保留不可变题目、条款、取证与验收。复制本工作区已发布模板可沿同一标识建立下一版；复制内置模板采用新标识。后续版本不会覆盖已采用版本；停用阻止新建评估，保留历史记录可读。

Owner、Operator 可以创建评估、保存答复并提交。提交允许携带缺口用于分诊，独立通过要求缺口和未完成的关联整改均清零且事实未过期。Owner、Reviewer 可以独立通过或退回；创建人、任何保存过答复的人员，以及采用证据或关联检查的证据贡献者均不能复核该评估。每次写入检查修订号，过期页面返回409。

答复中的证据必须属于同一工作区、同一资产及该活动，或该资产未绑定活动的检查；其他资产和租户的引用返回404。每次最多关联25个整改检查；证据题每题最多25条，全部答复最多采用100条不同证据。界面提供最近200条候选证据，已采用记录优先保留，截断范围有显式提示。

## 变更与定期刷新

处理活动详情支持 Owner / Operator 显式编辑全部业务属性，保留资产绑定。PUT 携带当前 `revision`，相同输入不增加版本、不写历史、不触发过期；冲突返回409并保留未保存内容供核对。处理活动变更通过同事务钩子标记相关评估过期，生成一条待重评任务并保留审计事件。独立复核前再次获取事实，防止来源或活动变化后沿用旧结论。已提交或通过的采用事实不被周期刷新覆盖；发生变化时仅标记过期并建立重评任务。

Go服务启动每10秒运行一次后台评估worker，单轮最多5秒、处理25条，关闭时随服务取消；后台调用 `Store.RefreshDueAssessments(ctx, limit)` 刷新到期机器事实，`limit` 为1—50；每个评估间隔为5—43200分钟，默认1440分钟。刷新覆盖已通过记录，以发现后续变化。尚在草稿/退回状态的负责人可刷新并采用新范围；活动范围变化会清空旧答复及检查关联，需要重新核对。已通过评估保留原结论和快照，重新创建评估处理变化。

## 报告与接口

JSON 与 HTML 报告包含采用模板及发布版本、各题条款、活动快照、带来源事实、答复、引用证据、缺口/风险、检查编号及独立复核状态。提交和通过时冻结报告；后续导出保留该次采用内容，并叠加当前过期/重评标识。历史工作流事件保留相应快照。HTML 使用自动转义。

活动详情使用 `PUT /api/v1/workspaces/{slug}/activities/{id}`，输入原有全部 `ActivityInput` 加 `revision`。每次真实变化保存 before/after、修订号、操作人和时间。`GET /activities/{id}/history?before=&limit=` 可分页读取（默认50，最多100）；`GET /activities/{id}/history/export` 导出 JSON，超过1000条明确返回422并要求分页提取，避免静默丢记录。各路径共同带工作区前缀，历史只对成员可见。活动创建与修改共享一个事务锁以固定评估关联集合，修改先锁评估再锁活动，避免与评估刷新互锁。

所有接口继承登录、工作区成员隔离和浏览器写操作 Origin 校验。共同前缀为 `/api/v1/workspaces/{slug}/assessments`。

| 方法和相对路径 | 用途 |
| --- | --- |
| `GET /?kind=&status=` / `POST /` | 最近100条评估 / 创建 |
| `GET /{id}` / `PUT /{id}/answers` | 详情 / 带revision保存答复与checkIds |
| `POST /{id}/review` | `revision, action: submit/return/approve, note` |
| `POST /{id}/refresh` | 编辑角色采用当前事实 |
| `GET /{id}/export?format=json` 或 `html` | 导出采用报告 |
| `GET /templates` / `POST /templates` | 已发布版本和草稿 / 创建或复制草稿 |
| `PUT /templates/{id}/draft` | 带revision编辑草稿 |
| `POST /templates/{id}/publish` | 带revision发布草稿 |
| `POST /templates/{revisionId}/disable` | 停用本工作区发布版本 |

可通过真实 PostgreSQL 验证模板版本固定、租户/角色隔离、独立性、未知业务条件阻断通过、已采用旧证据保留、周期过期及冻结导出：

```sh
cd backend
PLUME_STORE_TEST_DSN='postgres://localhost/disposable_test' go test ./internal/store ./internal/httpapi -run 'TestAssessment' -count=1
```

界面沿用控制台浅色主题，路由 `#/{workspace}/assessments`，详情 `#/{workspace}/assessments/{id}`。来源不足时继续显示待核实，不生成无事实支撑的通过结论。

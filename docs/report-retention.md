# 自动报告归档与留存

「历史报告与留存依据」管理本工作区 PostgreSQL 自动采集生成的报告归档。它不代表全平台所有记录的统一留存策略。

新归档和未核定用途的存量归档默认处于 `review_required`，继续保留。应结合实际用途确定依据、期限与保全要求，并安排独立复核；未核定记录会持续占用存储，不因数量窗口而自动视为可删除。

## 查询与核验

1. 从合规报告进入历史归档，逐页查看来源、采集运行、归档结果和留存状态。每页最多展示 50 项，继续读取较早归档。
2. 选择一项归档，核对生成时的实际范围、留存修订、保留依据、截止时间和保全保护。
3. 对可用报告点击“核验本地内容与摘要”。列表中的 `recorded` 仅表示已登记摘要；只有本次完整性接口实际读取并核对后，页面才显示 `verified`。
4. 按归档编号读取留存与导出准备历史。原报告被批准轮换后，仍可查询必要的删除墓碑；墓碑不会恢复或替代已删除的报告正文。

本地完整性采用报告和汇总元数据的 SHA-256，规范化口径为 PostgreSQL JSONB 文本的 UTF-8 字节。预览与导出也由服务端核验，不匹配时不输出文件。本地摘要验证不等于外部不可变存储、远端签名或监管收件确认。

## 保护与独立决定

| 动作 | 权限与条件 | 结果 |
| --- | --- | --- |
| 设置保全 `hold` | 负责人或经办人，填写实际依据 | `legalHold=true`，保全保护独立于日期 |
| 设置或延长期限 `extend` | 负责人或经办人；新截止须带时区、晚于当前时点且长于原期限 | `state=retained`；不能借此缩短原保护 |
| 独立解除保全 `release_hold` | 负责人或复核人，采用当前工作区真实检查证据；回避既往保护贡献者及所用证据作者 | 解除保全标志；不自动批准轮换 |
| 独立批准轮换 `allow_rotation` | 负责人或复核人独立判断；须有真实证据、无生效保全，且保留期限已到或未设期限 | `state=rotation_allowed`，具备参与后续轮换的资格 |

到期不会自动解除保全。批准参与轮换也不表示该文件已立即删除；数量轮换只处理明确放行、无保全且期限允许的归档。页面展示的每任务数量窗口不能替代对真实保留义务的逐项判断。

在编辑区选择动作、填写依据；独立解除或放行时输入真实检查编号，读取并选择其中的证据。服务端校验工作区归属、角色、贡献者回避和原留存修订。发生冲突时保留操作草稿，重新读取并核对最新修订后再提交。

若归档曾设置保全，独立解除或批准轮换所用证据的观察时点须不早于最近一次设置保全的时点。不能用旧决定的证据解除新保全；过早的证据会被拒绝，须取得相应阶段的新证据后再复核。

## 导出准备与外部保留

HTML 和 JSON 下载在服务端产生 `prepared` 事件，保存导出格式、实际导出字节数和摘要。浏览器还会核对响应 `Content-Digest`；实际字节不匹配时不发起文件保存。

`prepared` 只表示服务器已经准备导出内容，不证明浏览器已收到或保存文件。当前 `externalStorageStatus=unverified`，不宣称已写入外部 WORM、对象锁存储或完成独立长期存档。实际外部保留与收件仍需对应系统的证据。

## API

基址为 `/api/v1/workspaces/{slug}/reports/archives`。工作区成员可读，写入动作按上表权限校验。

| 方法与路径 | 用途 |
| --- | --- |
| `GET ?cursor=&limit=50` | 归档分页；返回 `items`、`nextCursor`、`hasMore`、轮换窗口与范围说明 |
| `GET /{id}` | 核验后读取原报告 JSON |
| `GET /{id}/integrity` | 实际核验报告与汇总 SHA-256，返回摘要、字节数、算法与规范化口径 |
| `GET /{id}/export?format=html` 或 `json` | 核验后准备导出，并记录 `prepared` 事件 |
| `POST /{id}/retention` | `{revision, action, basis, retainUntil?, evidenceId?}`，返回更新后的归档元数据 |
| `GET /{id}/retention-history?cursor=&limit=50` | 独立决定、准备导出和轮换墓碑分页 |

列表中的 `retention` 含 `revision`、`state`、`retainUntil`、`legalHold`、`holdReason`、`basis` 和贡献者信息；摘要字段为 `contentDigest` 与 `summaryDigest`。导出响应包含 `Content-Digest`、`X-Archive-Digest`、`X-Export-Receipt-Id`。

变更必须携带原 `revision`。字段或证据引用无效时核对输入，角色或独立性不满足时改由符合条件的账号处理；修订冲突时重新读取，不自动覆盖。完整性失败时核查本地归档来源，不把再次下载或历史墓碑视为内容已经恢复。

# 开发交接：赤翎全量桌面 UI

用户授权：全部页面先完成设计，再推给主对话开发；手机端适配延期。此包包含53个桌面页面与关键状态，覆盖19个现有一级模块。浏览器打标不在功能范围。

## 先后顺序与入口

主对话先完成正在进行的OpenMetadata/Wazuh真实实例联调、取证整改复测和报告验收，再按此包重做全平台桌面UI。该包尚未修改主项目任何Vue、配置、Git或数据。

- 目录：`index.html`，可双击或浏览器打开。搜索、分组、每页入口都可用。
- 逐页真值：`preview.html?screen=编号`与`renders/`的完整PNG。HTML/CSS为可直接检查尺寸和组件的设计源，内容是静态合成样例，不发送业务API。
- 页面映射：`manifest.json`、`PAGE-CONTRACTS.md`；现有Vue文件与实际路由逐项关联。
- 视觉来源：`images/`内10张全幅ImageGen基准稿，及`board-08-11.png`关系场景图板。不是声称53张均由ImageGen逐张生成；完整53页由同一ImageGen视觉系统进行确定性设计还原，避免图像文字和业务枚举漂移。
- `prompts/`与上级目录保留ImageGen提示词；`jobs.cjs`记录全部范围，手机端4项延期。

## 视觉与布局规范

深靛蓝216px导航、64px顶栏、24px内容边距、16px模块间距、12px面板圆角。工作区浅色、文档白底、图谱深蓝。字体沿项目本地Grove Sans SC（思源黑体派生子集）；源字体及OFL附在assets，主工程已有时复用。主操作蓝、关系青、AI及候选紫、风险珊瑚红。精确tokens见`tokens.json`，控件样式与规范见50–52页。

羽毛是信息布局语言：图谱的轴与枝表达有依据的节点关系，工作流页用轴串起取证到复核，台账和表单保持密度与阅读。主图需实现为可交互SVG/现有图组件，不能把整张设计稿铺成网页。

## 实施方式

1. 用19个现有导航入口与53项设计清单建立实施勾选表，保留全部功能和深链接。
2. 先统一全局框架、tokens、字体、按钮、表格、tabs、表单、抽屉和状态，再逐页按设计更换布局与细节；不只改全局颜色或首页。
3. 将预览的占位指标、趋势、人员、时间、来源和记录替换为实际接口数据。缺少真实数据的部分展示空/未知/过期，不补造统计。
4. 保持当前后端权限、独立审批/复核、证据时序、版本冲突、重放和范围限制。
5. 按逐页规格逐项完成桌面视觉与实际功能验收，再发布本地Docker。

## 图像文字的校正优先级

逐页HTML预览、PAGE-CONTRACTS与实际API契约优先于ImageGen中示意文字。部分原稿会自动添入不存在的导航、标准、分类或来源名称，只采用其视觉结构，不把这些文本实现成新能力。特别是：

- 保留全部19现有导航，不新增图稿中的MDM、质量或额外风险模块。
- 数据属性采用当前业务数据/个人信息/敏感个人信息；业务级别采用当前内部/机密；法定类别使用待认定/一般/重要/核心，三者独立。
- 标准名称、编号、版本、资料状态来自实际标准库；不复制图稿虚构条款数或示例法规年份。
- OpenMetadata标签或所有者不是源数据库ACL证据；Wazuh事件和PostgreSQL直接授权证明不能互换。
- 连接成功、来源采集成功、整改回执、来源复测、独立通过分别呈现；观察缺失不等于风险消除。
- 旧证据显示当时内容；新结果不回填旧快照。
- 所有导出、筛选、预览、配置与动作绑定已有接口；新接口需要单独判断，不从图像自动推导。

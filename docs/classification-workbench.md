# 分类分级工作台

本轮在已有分类标准库、客户侧发现采集和单资产分类确认上，补齐统一台账、业务分类目录、批量确认、发布复核和交付接口。自有规则识别引擎为默认能力，AI 模型接入由用户自主配置。页面入口为「分类分级」；场景入口保留 `?scene=` 导航上下文，台账范围由显式筛选决定。

## 使用流程

1. 在「多源自动发现」或已有 PostgreSQL 自动采集中确认来源、授权范围和实际覆盖；在台账检查表/字段身份及来源路径。
2. 按业务选择已登记标准，核对自动识别线索、条款条件和缺失事实。单资产继续使用「确认 / 依据」查看当前值、自动快照和完整变更历史。
3. 对适用条件一致的当前页资产执行批量确认。请求携带每项资产修订号，任一版本变化时整批拒绝。业务目录可保持原采用值、明确清除，或重新采用当前启用节点。
4. 对需要重新核对的来源取得新采集，再选择已完成人工确认且具有已知数据属性、内部级别和标准的资产，提交发布快照。法定类别仍可保留为待认定，继续补充实际适用依据。
5. owner/reviewer 中独立于提交人和所选资产分类经办人的人员复核。通过后才可导出；退回保留复核意见。后续分类、规则或来源事实变化不改写原发布快照。

UI 仅选择当前页资产，翻页或修改筛选会清空选择。API 单次批量确认和发布接受 1–200 项；台账每页最多 100 项。业务目录最多 200 个节点、5 层，修改时校验目录版本与循环关系。

## 自有识别引擎与可选 AI

「识别引擎与 AI」展示服务端报告的本地引擎版本 `scarlet-local-v2`、关键词/RE2 正则/精确词典规则，以及邮箱、手机号、身份证校验位和银行卡 Luhn 格式能力。规则校准、采用标准、条款事实和人工确认沿用前述流程。默认模式为 `local`，无需配置 AI 服务或凭据即可运行本地识别，也不会发起 AI 推理。

工作区 owner 可新增或修改模型配置，填写经证书与主机名验证的 HTTPS 基础地址、`chat_completions` 或 `responses` 协议及任意实际模型标识。点击「测试连接 / 获取模型」才读取该服务的模型列表，不发送资产信息；服务不支持列表接口时仍可手动填写模型。模型服务的实际协议实现、访问权限与费用由使用者选择和核对。

API 密钥为只写字段，不随配置读取返回明文。页面使用密码输入，更新时留空保留已保存值，也可明确清除；修改已保存密钥的服务地址时，必须更换或清除密钥。输入在请求返回、关闭编辑或离开页面时清空，不写入浏览器本地存储。服务端使用 `SCARLET_CLASSIFICATION_AI_KEY` 指定的 64 个十六进制字符（32 字节）密钥加密保存凭据；尚未配置加密密钥时页面显示实际状态，不能保存 API 密钥，本地引擎仍可用。部署需访问专用模型地址或私有 CA 时，分别配置 `SCARLET_CLASSIFICATION_AI_HOSTS` 和 `SCARLET_CLASSIFICATION_AI_CA_FILE`，TLS 验证继续启用。

模型配置的元数据发送授权默认关闭。owner 明确允许后，才可将已启用的配置设为 `hybrid` 模式的默认模型。owner/operator 在台账选择实际资产，读取当前资产修订对应的发送预览，再逐次点击「生成 AI 参考建议」；查看设置或切换页签不会自动调用模型。

预览来自服务端与实际推理相同的元数据投影，包括资产名称、系统、对象类型及最多 50 个字段的名称和类型，总量不超过 32 KiB。原始记录、业务值、字段注释、凭据和平台资产 ID 不发送给模型。选中资产或模型配置版本变化时清除旧预览；推理保存前再次校验资产及配置版本、启用状态和发送授权。

AI 返回值限定为数据属性、内部敏感级别和理由。建议独立保存模型、配置版本、资产分类修订和生成时间，历史版本明确标记；不自动写入分类、不提供法定类别结论，也不代替人工分类确认及独立发布复核。调用模型可能产生所选服务费用。当前验收覆盖两种协议的隔离 HTTP/TLS fixture、实际请求与建议保存流程，尚未配置真实模型服务，未据此确认某家供应商或真实业务数据的识别效果。

## 来源、范围和时效

客户侧发现任务明确绑定工作区、来源、数据库与授权范围。计划下发的识别规则、采集返回的对象，以及平台保存的标准和分类修订共同界定本次来源清单；命中与评估只用于该批次实际观察到的对象。字段记录采用自己的真实资产身份，不从同名字段或父表推定独立人工确认。

客户侧原生内容识别上传命中、已观察数和覆盖等结果，不上传原始业务值。浏览器规则测试使用用户填写的合成正反例，样本提交到本平台校准接口，不调用外部推理服务；响应仅返回序号、命中状态和统计。最多 100 条、单条 1,000 字符、请求 64 KiB；内容规则跳过超过 256 字节的样本，跳过项不计入精确率、召回率和准确率分母。

发现目录的当前有效性要求来源启用、授权仍有效、配置修订相符、最新采集成功且仍在计划周期 3 倍或至少 60 分钟的时效窗口内。连接测试失败、采集失败、漏表、暂停、配置或发布规则变化、分类后尚未取得相符来源事实，都可能要求重新采集。`needsReview` 独立于发布状态；没有发布过的资产同样可能需要重新核对。

旧 PostgreSQL 托管链路继续采用已有表级检查、字段元数据、自动判定与格式聚合能力；本轮不把其记录转换为新的多源发现任务，也不把已有表级资产补造成独立字段资产。其工作台校验包括最新运行、任务授权、连接目标、分类及标准是否仍对应，不能将这些校验解释为源数据库此刻无变化。需要发现目录的周期时效与字段级来源清单时，使用对应的客户侧发现链路，并核对实际返回覆盖。

分类发布只冻结明确选择的资产集合、采用标准和目录、来源事实与摘要。选中集合发布不表示工作区所有资产已分类，也不等于整库扫描或合规评估自动通过。有限格式样本、OpenMetadata 标签、所有者及未知源 ACL 继续按各自证据范围展示。

## 接口

以下路径均位于 `/api/v1/workspaces/{slug}`，使用现有会话身份及工作区成员权限；写操作同时校验角色和版本。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /classification/workbench` | 分页台账、工作区统计/分布、业务目录及当前来源复核标记 |
| `POST /classification/assets/batch-review` | 原子批量人工确认，逐项提交 `assetId`、`revision` |
| `GET/POST /classification/taxonomy`、`PUT /classification/taxonomy/{id}` | 读取、创建、修订业务目录；根节点使用 `parentId: null`，状态字段为 `enabled` |
| `GET/POST /classification/publications` | 最近 50 份发布记录、提交不可变快照 |
| `GET /classification/publications/{id}` | 获取选定快照、完整冻结资产与复核信息 |
| `POST /classification/publications/{id}/review` | `publish` 或 `reject`，执行独立性及当前事实校验 |
| `GET /classification/publications/{id}/export.csv`、`export.json` | 仅导出已发布快照；CSV 保留资产身份、采用依据及快照摘要，JSON 保留结构化快照 |
| `POST /discovery/rules/test` | 对当前规则运行合成正反例校准，不保存或发布规则 |
| `GET/PUT /classification/engine` | 读取引擎能力和模式；owner 按修订号保存 `local`/`hybrid` 与默认模型 |
| `GET/POST /classification/ai/profiles`、`PUT /classification/ai/profiles/{id}` | 读取无明文密钥的模型配置；owner 创建或修改连接、协议、模型、发送授权及密钥 |
| `POST /classification/ai/profiles/{id}/test` | owner 明确触发连接和模型列表测试，不执行资产分类 |
| `GET /classification/ai/input?assetId=…&revision=…` | owner/operator 读取与实际请求一致的受限元数据预览，不调用模型 |
| `GET/POST /classification/ai/suggestions` | 按资产读取历史建议；owner/operator 在混合模式下对指定模型、资产及修订显式生成建议 |

分页、过滤或发布读取不因 URL 中的业务场景参数自动缩小工作区范围。下游应保存发布 ID 和快照摘要，明确自己采用的版本；交付状态表示绑定接收方确认接收，不等于第三方内部应用完成。知识、训练及交付契约见[说明](classification-intelligence-and-delivery.md)。

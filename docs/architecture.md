# 系统架构

赤翎用 Go、Vue 3、TypeScript 和 PostgreSQL 建设可自部署及可托管的数据安全治理平台。服务端负责管理监管要求、数据资产、风险和控制证据。客户侧采集器连接已有系统，将经过筛选的结果交给平台。证据与实际源系统之间保留可回溯的引用。

## 系统边界

```text
业务和安全人员
        │ 同源 HTTPS
Vue 工作台 ──────────────── Go API
                                 │
                                 ▼
                         PostgreSQL plume schema
                            工作区 · 资产 · 证据
                                 ▲
                   版本化清单 / 授权采集端点
                                 │
客户侧 Go 采集器 ── 只读 API / 元数据 ── 客户现有系统
```

| 模块 | 职责和信任边界 |
|---|---|
| Vue 工作台 | 资产、集成、规则、评估、整改和复核的操作入口。前端权限提示由后端授权兜底。 |
| Go API | 按会话和成员关系确定工作区，处理业务写入、审计和导出。业务模块共用同一个部署单元。 |
| PostgreSQL | 保存工作区、账号、会话、资产、处理活动、导入、检查模板版本、监管检查、证据和审计事件。独立 `plume` schema 与 Django 预览分开，发布任务和运行身份分离。 |
| 客户侧 Go 采集器 | 在客户环境内连接源系统。凭据保存在客户侧，读取批准范围内的元数据或证据引用。 |
| 连接器 | 按能力标记资产发现、证据采集、控制验证或控制执行。执行类连接器单独授权，保留操作回执和复测结果。 |

PostgreSQL 资产可由平台托管定期采集，也可由客户侧采集器提交。托管连接仅访问部署允许的主机，密码加密保存。客户侧采集器使用可撤销的任务令牌定期提交资产或飞书权限观测。平台按任务核验工作区、来源和检查目标，将业务写入和运行记录放在同一事务中。源系统权限、服务商账号和日志原文留在客户环境。平台接收资产名称、源端标识或脱敏权限状态。 [自动采集配置](automation.md)

## 功能与接入边界

| 场景 | 平台功能 | 接入范围 |
| --- | --- | --- |
| 数据发现与分类 | 资产目录、识别规则、标准、人工确认与发布 | [多源发现](discovery.md)、[文件与指纹](file-content-and-value-evidence.md)及[分类工作台](classification-workbench.md)分别说明受支持格式、授权范围与采样缺口 |
| 检查与评估 | 版本化规则和问卷、取证、整改复测、独立复核和导出 | [模板与报告](templates-reports.md)、[专项评估](assessments.md)记录适用条件；技术结果不代替实质法律判断 |
| 权限观察 | 来源绑定的权限快照、整改与同范围新观察 | [飞书连接器](feishu.md)限定指定文档的直接协作者；真实租户权限与外部系统语义需独立验证 |
| 告警与运营 | 受限事件、风险研判、受控处置与回执 | [安全运营](security-operations.md)和[事件调查](data-security-events-and-cases.md)仅采用已授权来源与支持动作 |
| 身份与审计 | 工作区角色、独立审批、OIDC/SCIM、网关审计 | [网关治理](ai-gateway-enterprise.md)说明身份、占额、节点认证及独立留存边界 |
| AI 与 Agent | 来源授权、模型输入输出、固定工具目标和任务约束 | [AI能力范围](ai-data-security-capabilities.md)及各执行器文档明确协议、格式和接入要求 |

每个连接器应标明观察范围、采集时间、权限限制、采集失败和覆盖缺口。接入需核对实际版本、地域、许可证、授权和返回字段。告警、审批、配置及复测是不同类型的证据，独立审核决定控制是否通过。

## 安全与数据一致性

- 工作区访问由数据库中的成员关系判定。查询、导入和导出均使用服务端解析的工作区 ID；跨工作区访问、只读角色写入和失效会话应被拒绝。
- 监管检查写入锁定同一检查记录，并同时保存审计事件。复核绑定提交版本，创建人、提交人和证据登记人需要回避。飞书检查的提交门槛包含同一目标的快照与整改时序。
- 合规检查报告在同一只读事务中读取检查、证据与审计事件。报告基于已创建的检查和对应模板版本，按范围限制记录总量。 [模板与报告说明](templates-reports.md)
- 资产清单导入限制为 512 KiB、1,000 项和固定字段。工作区、提供方、来源和批次构成幂等键，同键异内容返回冲突。同一资产引用重复采集保留原记录，清单缺项只表示本次未观察到。
- Web 会话使用随机令牌，数据库存摘要，HTTPS 模式使用受保护的 Cookie。写请求校验同源。数据库和远程采集使用 TLS 证书与主机名校验。回环明文仅用于显式启用的本地开发。
- 托管验收加入企业身份、登录限速、连接器专用凭据、数据退出与删除、审计导出、备份恢复及租户隔离压力验证。正式服务按实际适用规则确定存储、运维和供应商边界。

## 部署与迁移

构建、数据库迁移和启动步骤见[项目说明](../README.md)。升级应先备份并执行对应迁移，再启动应用与实际启用的采集器；保留现有数据卷、密钥和来源配置。

历史 Django 数据可通过一次性命令导入同库的 `plume` schema。命令默认预检，正式导入及账号激活要求见[Django迁移手册](django-migration.md)。来源连接器的配置和验证步骤以对应模块文档为准；不把界面配置成功视为实际来源接入完成。

# 赤翎架构设计

赤翎用 Go、Vue 3、TypeScript 和 PostgreSQL 建设可自部署及可托管的数据安全治理平台。服务端负责管理监管要求、数据资产、风险和控制证据。客户侧采集器连接已有系统，将经过筛选的结果交给平台。证据与实际源系统之间保留可回溯的引用。

## 系统边界

```text
业务和安全人员
        │ 同源 HTTPS
Vue 工作台 ──────────────── Go API
                                 │
                                 ▼
                         PostgreSQL plume schema
                            工作区 · 资产 · 证据
                                 ▲
                   版本化清单 / 后续专用采集端点
                                 │
客户侧 Go 采集器 ── 只读 API / 元数据 ── 客户现有系统
```

| 模块 | 职责和信任边界 |
|---|---|
| Vue 工作台 | 资产、集成、规则、评估、整改和复核的操作入口。前端权限提示由后端授权兜底。 |
| Go API | 按会话和成员关系确定工作区，处理业务写入、审计和导出。业务模块共用同一个部署单元。 |
| PostgreSQL | 保存工作区、账号、会话、资产、导入、监管检查、证据和审计事件。独立 `plume` schema 与 Django 预览分开，发布任务和运行身份分离。 |
| 客户侧 Go 采集器 | 在客户环境内连接源系统。凭据保存在客户侧，读取批准范围内的元数据或证据引用。 |
| 连接器 | 按能力标记资产发现、证据采集、控制验证或控制执行。执行类连接器单独授权，保留操作回执和复测结果。 |

Go 预览通过人工提交版本化资产清单和飞书权限清单进行接入。源系统权限、服务商账号和日志原文留在客户环境。平台接收资产名称及源端标识，名称本身也按客户数据管理。托管模式准备接入独立、可撤销的采集身份和候选证据收件箱，客户可核验采集范围和投递记录。

## 功能覆盖与集成顺序

| 场景 | 赤翎负责的功能 | 现有系统及接入次序 |
|---|---|---|
| 数据发现与分类 | 资产目录、来源、处理活动、标签审批、重要和核心数据认定依据 | **首批已实现** PostgreSQL、OpenMetadata 表清单。接下来映射阿里云 DSC、腾讯云 DSGC、华为云 DSC 的分类和扫描证据。 |
| 法规与评估 | 规则适用性、版本、工业行业包、风险评估、审计底稿、整改和复测 | **已迁移** 14 条基础规则、检查、取证、整改、复核和导出。后续补规则适用性与评估报告。 |
| 访问控制与供应商共享 | 接收方、审批、到期、源权限核验和撤权复测 | **已实现采集**飞书新版云文档指定直接协作者的权限快照，真实租户待联调。飞书审批和阿里云 OSS 为后续接入。 |
| 告警与防泄漏 | 告警接收、风险研判、证据引用和事件工单 | 接 Wazuh 和火山引擎飞连的可外发字段。控制台只展示已纳管来源和覆盖范围。 |
| 日志、加密与备份 | 日志留存核验、密钥状态、恢复演练证据 | 对接阿里云 SLS、OpenBao 或客户 KMS、客户现有备份系统。恢复演练和备份任务分别留证。 |
| 身份和授权 | 工作区角色、审计、审批与复核分离 | 用 Keycloak 或企业现有 OIDC 接身份，平台保留工作区授权。 |
| 个保、出境与数据处置 | 个人信息处理台账、影响评估、对外提供、出境和删除证据 | 先接审批、工单及源系统回执，按客户实际处理关系核定适用性。 |
| AI 使用 | 模型供应商、数据类别、地域、留存、知识库和工具风险 | 与其他处理活动共用规则及证据。后续接 Higress 等网关和已批准的检索、工具执行点。 |

PostgreSQL 连接器使用仅有 schema 访问权的账号进行验证。OpenMetadata 当前覆盖模拟接口测试，包括服务范围、分页和重定向处理，真实实例联调列入接入验收。集成目录中的候选项依据接口或导出文档。接入验收以实际客户版本、地域、许可证、授权和返回字段为准。每个连接器应标明观察范围、采集时间、权限限制、采集失败和覆盖缺口。告警、审批、配置及复测是不同类型的证据，独立审核决定控制是否通过。

## 安全与数据一致性

- 工作区访问由数据库中的成员关系判定。查询、导入和后续导出均使用服务端解析的工作区 ID。首个版本测试跨工作区拒绝、只读角色拒绝写入，以及注销后会话失效。
- 监管检查写入锁定同一检查记录，并同时保存审计事件。复核绑定提交版本，创建人、提交人和证据登记人需要回避。飞书检查的提交门槛包含同一目标的快照与整改时序。
- 资产清单导入限制为 512 KiB、1,000 项和固定字段。工作区、提供方、来源和批次构成幂等键，同键异内容返回冲突。同一资产引用重复采集保留原记录，清单缺项只表示本次未观察到。
- Web 会话使用随机令牌，数据库存摘要，HTTPS 模式使用受保护的 Cookie。写请求校验同源。数据库和远程采集使用 TLS 证书与主机名校验。回环明文仅用于显式启用的本地开发。
- 托管验收加入企业身份、登录限速、连接器专用凭据、数据退出与删除、审计导出、备份恢复及租户隔离压力验证。正式服务按实际适用规则确定存储、运维和供应商边界。

## 迁移和发布

1. **已实现的垂直切片**。Go 账号与工作区、资产登记与分页、PostgreSQL 和 OpenMetadata 采集、Vue 集成目录与导入记录。Django 预览继续在现有路径运行。
2. **已迁移的监管工作流**。Go 支持规则、检查、取证、整改、复测、独立复核和导出。历史 Django 记录保留在原应用，处理活动与历史记录迁移另行推进。
3. **客户侧采集和国内产品联调**。飞书直接协作者采集和整改流程已通过模拟接口与浏览器验证。真实飞书租户联调、采集身份和候选证据收件箱留作后续交付。 [飞书联调手册](feishu.md)
4. **按行业和场景拓展**。以同一批真实任务验证证据覆盖、取证时间、接入成本和复测通过率。按适用场景推进个保、出境、AI 和事件模块。

社区版保留核心治理流程、连接器协议与证据导出。未来的托管、实施和支持服务分别公布计价单位与交付范围。

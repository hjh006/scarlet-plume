# API 安全

赤翎当前在「API 安全」分析提交的 OpenAPI 契约，自动把接口写入资产台账，把需要核对的发现接入监管检查和取证流程。扫描的输入是契约元数据，鉴权声明和敏感字段候选需要结合实际部署核验。

运行时入口已支持独立 Go Agent、已有网关脱敏日志和跨语言 OTLP，参见 [API 运行时观测](runtime-security.md)。

## 开始扫描

可使用仓库内的 [合成 OpenAPI 样例](../examples/openapi-security-sample.json) 验证整个流程。

1. 工作区负责人或经办人打开「API 安全」，输入来源名称，选择 OpenAPI 3.0 或 3.1 的 JSON 文件，点击「开始扫描」。界面支持不超过 480 KiB 的文件，每份契约最多分析 200 个 HTTP 操作。建议同一服务使用稳定的来源名称，使用路径模板并在上传前移除真实凭据和业务示例。
2. 扫描详情显示按 HTTP 方法和路径识别的接口、鉴权声明、疑似敏感字段、风险信号和关联的资产与检查。字段识别覆盖参数、请求体和响应体中可解析的结构。组件引用限定在本文件的 `#/components/`，未解析的引用会计数提示。
3. 有风险信号的接口会自动创建或关联 G03 检查，登记包含扫描编号和观察摘要的证据。操作人员沿用现有的整改、复测和独立复核流程。工作区合规报告汇总这些检查及已登记证据。
4. 在详情页导出结构化 JSON，供复盘或存档。最近扫描列表展示 25 次结果。工作区成员可以读取本工作区的扫描和导出。

系统保存派生结果及其摘要。资产按工作区、来源、HTTP 方法与路径归并。同一来源的分析结果与最近一次相同时，返回已有扫描。可识别事实变化时保存新扫描，未变化的事实证据去重，已进入复核或整改的检查保留原工作流状态。新版契约缺少的接口资产仍可在历史中追溯。

| 自动分析 | 验收时观察 |
| --- | --- |
| 鉴权声明 | 分别上传声明鉴权、允许匿名、未声明和引用无效的操作，结果区分四种状态 |
| 疑似敏感字段 | 使用含 `customerEmail` 或 `format: email` 的参数、请求或响应结构，扫描结果标注字段位置与类别 |
| 契约风险 | 匿名操作声明邮箱响应时出现敏感响应与鉴权核对信号。返回疑似凭据、路径含对象标识、接口标记弃用时分别提示核验 |
| 取证和复核 | 由风险操作进入 G03 草稿，核对证据中的扫描编号与观测摘要。重复提交同一文档后，接口资产、检查和证据数量保持一致。独立复核人从检查流程作出复核决定 |
| 导出和隔离 | 下载扫描 JSON 核对接口和发现，通过同一工作区的合规报告核对相关检查及证据。其他工作区访问扫描详情或导出时应被拒绝 |

## 后续阶段及验收

| 阶段 | 赤翎自研 | 对接现有系统 | 验收标准 |
| --- | --- | --- | --- |
| 1. 发现与覆盖 | 统一接口身份、版本及证据来源，比较契约与已部署或已观察到的接口 | 首个 API 网关及 CI 中的契约发布 | 在测试环境准备已登记、仅网关发现和已弃用但仍有流量的接口。接入后展示三类差异及来源时间，重放同一批次时资产保持稳定。凭据撤销后停止采集并在界面显示失败 |
| 2. 运行时检测 | 数据类型与风险规则、事件聚合、证据登记 | 现有网关或 WAF 的脱敏日志与安全事件 | 合成流量触发敏感响应和异常访问用例。事件可回溯至接口、时间窗和脱敏字段类别，重复事件归并。核对平台入库及导出仅包含约定的元数据 |
| 3. 测试、复测与处置 | 规则映射、工单和复测状态、审批及审计 | CI 动态测试、工单系统、现有网关或 WAF 执行端 | 在授权测试环境用双账号复现对象级越权。修复后自动重跑并保存前后证据，独立复核人核对结论。验证一条经审批的网关处置、执行回执与回滚 |
| 4. 数据流与场景报告 | 关联接口、字段、处理活动及对应证据，汇总审批与整改结果 | 现有调用追踪、数据目录和审批系统 | 用合成场景追踪 API → 应用 → PostgreSQL 字段，关联一次对外共享、出境或 AI 使用活动。报告标出已观测链路、采集时间与缺口，留存引用便于独立复核 |

当前交付覆盖契约静态分析及检查取证，也已支持从独立 Agent、网关日志和应用探针自动收集运行时路由，并与 OpenAPI 基线对照。已支持将未登记或已弃用但返回 2xx 的操作变为监管检查，自动保留初始与复测证据，并允许独立复核。表中尚未完成的验收项仍属后续交付。契约中的对象路径提示用于安排授权测试。实际的对象级越权、影子接口、运行时暴露、阻断回执与数据流向由对应环境的实测证据确认。

# 数据外发、数据库审计与运营调查

2026-11-12 实现。本轮范围是数据外发、数据访问审计和相关调查证据，不包括通用终端防护、身份访问平台或全套厂商产品。界面入口在风险监测与处置、数据共享与委托及AI数据安全下的“数据外发与事件调查”，并复用识别与证据工具。调查面向已经授权接入的事实，不扫描未授权终端，也不将通道名称当作已有内核拦截能力。

## 来源数据与权限

已有 `security_events` 来源令牌继续使用 `POST /api/v1/operations/security-events`。`SecurityEventInput` 可携带严格 `dataContext`：数据类别、通道、操作、来源执行声明、捕获状态，以及客户侧HMAC主体/设备/数据库/对象/语句引用、文件SHA256、实际目的地域名、可选记录数和本地策略摘要。不接收用户名、文件路径、文件正文、SQL、参数或提示词字段；引用须为64位小写十六进制。主体/设备引用只在同一来源内比较，不能自动合并不同工具中的员工身份。

`outcome=activity`仅保存正常活动审计，不创建G03风险待办或其他监管检查，也不触发自动风险通知；它不表示既有风险已经清除。允许的受控复制、允许的AI出口调用及正常pgAudit操作都使用activity；源端策略阻断或未知决定仍使用observed进入风险取证链。Wazuh FIM低/中级变化作为活动，高/严重级告警保留风险发现；不能仅因一条正常READ就创建风险。

上下文参与事件去重摘要及检查范围。不同主体、设备、文件、通道、数据库目标或目的地的清除声明不能清掉另一范围的检查。旧事件没有上下文仍是旧事件，不自动补造成终端或数据库活动审计。来源撤销/维护人权限失效在新查询中显式标识；冻结调查保存当时状态。

`GET /data-security/events` 在SQL中先按工作区、来源、主体/设备引用、通道和时间筛选，再采用最多200条。`POST /data-security/cases` 只允许owner/operator，将这次来源事件、同源引用关联、预算截断和覆盖缺口冻结并生成摘要。查看与HTML/JSON导出可由工作区只读角色使用；人工误报/预期活动/继续调查反馈以独立备注保留，不能更改原始事件或自动关闭监管检查。

## 客户侧接入

- 原 `event-bridge -format wazuh` 行为保留。显式 `wazuh_context` 仅投影有真实agent ID与syscheck对象的FIM事件；设备、用户和路径在本地做HMAC，不上传完整告警。FIM不提供文件内容类别，捕获标为partial，不能把文件变化当作已发生USB、打印或邮件外发。
- `event-bridge -format pgaudit` 接收PostgreSQL JSON日志中的pgAudit CSV消息，保留原日志时间、会话/语句标识及操作类；角色、数据库、会话和对象在客户侧匿名化。SQL与参数列不上传，不从语句类别推断实际返回行数。接入格式依据[pgAudit官方格式](https://github.com/pgaudit/pgaudit#format)及[PostgreSQL JSON日志](https://www.postgresql.org/docs/18/runtime-config-logging.html#RUNTIME-CONFIG-LOGGING-JSONLOG)。需要客户已配置真实审计日志；只有解析夹具通过不代表客户数据库已启用审计。
- 两个匿名化格式都要求源端 `SCARLET_EVENT_CONTEXT_KEY_HEX`（32字节十六进制密钥）及明确 `SCARLET_EVENT_CONTEXT_SCOPE`。密钥留在客户侧，不能写入平台或命令行。事件投递复用 `SCARLET_OPERATIONS_TOKEN` 与固定平台地址，不跟随重定向。
- 其他终端DLP工具可使用规范化上下文，但其通道、操作和执行结果是被授权来源的声明，须结合工具真实回执核验。平台不虚构全知或亿格云私有接口的直连兼容。

## 源端数据外发策略

`pkg/datasafety` 提供有界规则判断及客户侧SDK。策略包含版本、保护类别、允许通道、批准AI域名及是否阻止未批准AI目的地。域名精确匹配；AI和数据库通道与其kind双向一致，不能通过改kind绕过AI检查。捕获不完整时结果unknown，调用方不能把unknown当作允许。

`scarlet-data-transfer-guard` 实际执行一笔明确授权的文本文件复制。参数为本地策略文件、授权输入/输出目录、相对源与目标路径及幂等事件ID，可选本地生成的HMAC主体/设备引用。它拒绝目录逃逸与越界符号链接，不覆盖已有目标；只在规则允许时写入原始字节。阻断或未知均不创建目标，输出仅是可供event-bridge投递的结构化事件。

当前文本识别只支持TXT、CSV、JSON、JSONL内的邮箱、手机、校验有效身份证和银行卡格式。JSON/JSONL真实解码转义和标量，CSV检查语法；格式、深度、字数或令牌预算不足均unknown。未知扩展、容器/文档伪装或保护策略包含未实现类别时拒绝复制。此工具没有代替文件采集器的PDF/OCR解析，也不是操作系统范围的USB、剪贴板或打印拦截器。格式命中不证明真实人员身份或法定数据等级。

文件采集器另有[有界XLSX静态单元格识别](file-content-and-value-evidence.md#xlsx-单元格范围)，不会执行公式或跟随外链，未覆盖部分明确保留缺口。采集器支持XLSX不代表复制guard获得XLSX检查或放行能力；复制guard仍仅接受上述四类文本，遇到XLSX保持unknown并拒绝复制。

AI输入可显式接入原运行时代理的 `-ai-egress -data-policy`：固定HTTPS上游和批准POST路由，在转发前检查有界JSON及域名/类别策略；阻断或未知不抵达模型，允许请求只有在活动审计保存成功后才原字节转发。只有配置代理覆盖的请求受控，未接入终端AI、IDE或MCP通道仍未知。部署与双令牌要求见[运行时说明](runtime-security.md)。

该AI出口拒绝上游全部3xx并返回不含`Location`的安全502，防止客户端跟随307/308把POST正文带往另一个目的地；不会靠放松TLS实现。已允许的初始HTTPS跳段仍采用原字节，非重定向响应保留SSE流式传输；普通未启用AI出口的代理保留原有重定向行为。此保护不表示已检查模型响应正文或提示词语义。

## 规则关联与可选AI运营参考

调查快照按同来源内明确主体或设备引用形成事件链，展示具体事件号、通道和时间；无身份引用时保持单事件，不以同IP、相似文本或同一类别猜测同一个人。它不推断恶意动机。误报反馈不会无授权地改变检测策略或训练模型。

可选模型复用已加密保存的Chat Completions/Responses配置。工作区须明确启用混合模式，模型启用并允许元数据，调用者须逐次同意界面预览。只发送事件号、链编号、类别、规则、执行声明及冻结时来源/捕获状态，不发送主体/设备引用、文件摘要、SQL、提示词或真实身份；超过100条要求缩小调查范围。

模型只能返回有界摘要、风险参考级别、有效事件号、不确定性及建议。未知字段、虚构事件引用或密钥回显会被拒绝；建议不触发策略、处置、检查提交或独立通过。返回结果保存时再次核验当前引擎模式、模型启用权限/版本与调查摘要。协议夹具验证不能用于宣称生产模型精度。

## 验证范围

真实本地文件测试验证阻断时目标不存在、允许时字节一致、既有目标不覆盖、路径/符号链接越界拒绝、未知格式/预算不足保守拒绝。AI出口的本机TLS测试验证实际阻断、允许正文原字节转发、审计失败关闭、跨域307/308不重放及SSE首块及时到达；另域接收端通过正常证书校验的可达性检查，避免把TLS失败误报为策略阻断。事件桥有原生格式脱敏与确定性匿名引用回归；真实PostgreSQL/HTTP测试验证跨工作区与角色、范围先过滤、重放、固定调查、反馈不覆盖快照、模型逐次同意/仅本地禁外联、来源撤销及导出转义。实际厂商终端部署、全通道覆盖、数据库采集完整性及生产识别效果仍须在客户授权环境验收。

# AI运行时回执接入

控制台策略评估不执行模型或工具。客户侧`scarlet-ai-security-agent`记录真实执行阶段；本接入将其不含正文的耐久审计交付平台，作为认证来源报告保留，与独立复测分开。

## 创建独立来源

1. 在AI安全工作台保存配置，运行当前修订的实际引擎评测，由独立Owner/Reviewer发布。
2. Owner在“运行证据/部署”中选择已发布应用创建运行时来源。来源固定工作区、应用ID和已发布目录摘要，令牌只返回一次。
3. 将令牌放入客户侧只读、仅所有者可读的文件，避免写进命令参数、仓库或日志。管理端只保存令牌摘要。

客户侧模型/工具访问凭证与平台回执来源令牌用途不同，分别管理。回执令牌没有调用模型、读取文档或执行工具的权限。

## 投递本地审计

```sh
scarlet-ai-security-receipts \
  -platform https://security.example.com \
  -token-file /run/secrets/scarlet-ai-receipt-token \
  -audit-file /var/lib/scarlet-ai/audit.jsonl
```

私有CA可以通过`-ca-file`提供。仅本机合成验收可使用`-local -platform http://127.0.0.1:端口`。生产连接强制HTTPS、证书校验且不跟随重定向。

未指定审计文件时从标准输入逐行读取。投递器只处理审计，绝不重新执行模型或工具。成功记录以平台返回的回执ID确认；同一来源重投相同事件ID及内容是幂等的，内容不同则拒绝。投递失败保留客户侧原文件，不能将失败解释为动作未执行或已回滚。

每条JSONL最多64KiB，平台只接受结构化`AuditRecord`；额外正文、参数或凭据字段拒绝。当前来源最多接收20000条独立回执，达到容量后需新建来源、更新投递令牌并从尚未确认的记录继续投递。已确认旧事件可对原来源安全重试；更换来源不应从头将全部历史当作新运行。当前工作区最多100个活跃来源，已撤销历史不会占用活跃来源额度。

## 回执阶段与采用边界

| 字段 | 含义 |
| --- | --- |
| `decision` | 策略允许或拒绝，尚未证明执行发生。 |
| `prepared` | 执行前已写入耐久审计；此时进程可能在请求发出前或发出后中断，不能判断成功。 |
| `completed` | 客户侧报告的执行结果，包括成功、失败、未知或输出抑制。成功不等于最终客户端已收到响应，也不代替业务系统副作用核验。 |
| `current` | 来源未撤销、创建者仍有Owner权限，且绑定摘要匹配当前发布目录。仅表示绑定当前性，不证明在线、覆盖全部通道或控制已独立验证。 |

平台校验应用及目录摘要与来源绑定、事件与请求摘要格式、阶段、枚举、大小及时间窗口。当前接收最近7天、未来偏差不超过5分钟的观察，较早记录保留本地归档。源创建者权限失效或来源撤销后，令牌停止接收；历史回执保留。

新目录发布后旧来源记录显示历史绑定。应将新目录部署到客户侧，为新摘要创建相应来源，并重新执行正反用例。实际模型、知识源及工具接入仍由相应客户环境验收。

## 执行器版本与请求链核对

新执行器在每个审计阶段附带 `runtimeProtocolVersion`、`inspectionVersion`，MCP 工具还附 `mcpProtocolVersion`。平台分别显示：

- `supported_profile`：来源声明匹配当前支持版本；不是二进制远程证明。
- `unversioned`：旧记录未报告版本，保留历史证据和明确缺口。
- `unsupported`：来源声明的执行器、检测器或 MCP 版本尚不受当前平台支持；记录仍可保留，不升级为已兼容。

配置可通过 `requiredRuntimeProtocolVersion` 和 `requiredInspectionVersion` 要求精确执行版本，未知版本拒绝采用。运行版本、检测版本、配置摘要和测试包版本应分别核对；更改字段不自动刷新已有证据。

平台对新投递增加阶段一致性校验：决策和准备阶段不能声称已经尝试上游；准备阶段须为允许决策；执行成功必须有实际尝试和符合该类型的状态码；输出抑制、失败与未知结果不能同时声称允许成功。历史存量记录不被覆盖重写，矛盾内容在请求链中单列。

`runtime-evidence.requests` 仅关联本次分页和过滤条件内的事件片段，按来源、请求引用、请求摘要、目录摘要和执行器生成的 `attemptId` 分组。每次 HTTP 尝试使用新的随机引用，同一尝试的决策、准备和完成阶段保持同一引用；调用者不能自行指定。正常重试被防重放拒绝时，不会与第一次执行拼成时间矛盾。

它区分仅策略拒绝、等待批准、阶段不完整、阶段相互矛盾，以及阶段齐全的来源报告成功/失败/未知/输出抑制。主体、类型、版本及同阶段结果变化会产生调查项。接收乱序不会改变源端阶段次序判断；源端时间倒序单独提示。旧记录没有 `attemptId` 时，语义相同的阶段采用最早时点；不同阶段结果可能来自多次尝试，显示 `attempts_ambiguous`，保留无法区分的证据缺口。

只有完成回执而缺少决策或准备回执时，显示“不完整”，不认定完整执行链。只有准备而没有完成时，不能推断没有副作用。采样窗口、漏报、进程中断都可能造成阶段缺失；它们属于待核对证据，不能据此计算生产控制成功率。不同来源与不同请求摘要的阶段不会被拼接成一次成功。

## 来源令牌轮换

`GET .../ai-security/runtime-evidence` 中每个来源包含 `tokenVersion`。Owner 可向
`POST .../ai-security/runtime-sources/{source}/rotate-token` 提交：

```json
{"expectedTokenVersion":1}
```

操作要求有效平台会话和受信任 Origin。成功返回 `{source,token}`，新明文只显示一次且响应禁止缓存；复制到原投递器的受限 token 文件后重新加载投递进程。旧令牌在轮换事务提交后立即返回 401，没有双令牌过渡期。轮换保留原来源 ID、绑定摘要、容量计数与历史回执；不会更新到新目录。CAS 不一致返回 409，应刷新来源后再操作；已撤销来源或创建者已无 Owner 权限不能通过轮换复活。新目录仍需新建绑定新摘要的来源。

## 回执分页与过滤

`GET .../ai-security/runtime-evidence?limit=50&before=<nextCursor>` 返回原有
`sources/events/requests/coverage/limit`，以及 `hasMore/nextCursor`。还可按正整数
`sourceId`、`kind=rag|model|tool|output`、`outcome=allow|deny|approval_required|unknown`
过滤。省略页长为 100，显式页长必须为 1—200。未知枚举、重复/非法参数或不属于当前工作区的来源拒绝。

按事件 ID 倒序读取，将服务端 `nextCursor` 原样作为下一次 `before`。游标绑定工作区、来源与过滤，不可跨筛选复用；改变筛选后清空游标。来源预览最多显示 100 项，旧已撤销来源的事件仍可用其 ID 查询。每页 `requests` 只关联该页的阶段；跨页阶段缺失不能据此认定没有执行或副作用。轮换、撤销、分页及版本状态均不构成独立的远端执行证明。

# 赤翎 Windows 企业终端部署与验收包

本包交付Windows x64/ARM64执行器、安装/移除脚本、显式目标模板和合成数据验收清单。当前没有Windows测试机：构建、纯测试和协议验证不代表实机通过，清单默认全部`not_run`。不得把配置回读或本包哈希正确当成数据外发已被阻止。

## 控制与边界

- USB：Windows可移动存储类拒写策略；不等于所有USB总线/协议。生效可能需要重启或设备重新打开，执行器不自动重启。
- 打印：只暂停模板明确列出的本地打印队列。当前在印任务可能继续，任务仍能入队；不能声称全部打印流量或所有打印机已经拦截。远程队列/任意服务器句柄不允许。
- 剪贴板：只限制RDP剪贴板重定向。需要按平台提示重连/重启并验证；不拦截本地全部应用的剪贴板。
- 已加入AD域、受MDM管理、原策略已配置或归属无法确认时，注册表控制器拒绝接管。组织管理员应通过现有GPO/MDM渠道管理这些策略；本包不覆盖域管设置。
- 原生策略只能`block_all`，不能靠队列/变化日志推断敏感内容。原先显式受控动作的敏感格式检查继续独立使用。

## 部署

1. 从平台为该机器登记独立安全事件来源，保存一次性来源令牌。准备能被Windows机器验证证书的HTTPS平台地址。Mac本机演示端口仅绑定回环，不自动暴露给外部Windows终端，也不关闭TLS验证。
2. 复制`config.example.json`到包外的部署目录，填平台origin、业务scope，明确选择需要的控制。默认没有选任何目标，必须由管理员启用至少一项；打印机填写实际本地测试队列名。空`deviceId`会在首次配置时随机生成并保护，后续不能随意换来源/设备身份。
3. 使用 Windows PowerShell 5.1（Desktop / .NET Framework），再执行`Test-ScarletDeployment.ps1 -Mode Static`核对包文件SHA256。SHA256只证明完整性，不是厂商代码签名或Windows兼容性证明。按组织现有签名、WDAC和PowerShell执行策略审批本包，不修改或绕过保护。
4. 以管理员身份运行`Install-ScarletEndpoint.ps1 -Configuration <包外配置.json>`。来源令牌通过安全输入临时传给子进程；HMAC密钥自动生成或由管理员受保护环境注入。连接配置和恢复原值用Windows机器DPAPI加密，目录只允许SYSTEM/Administrators，不写明文令牌或打印机名到平台。
5. 安装只注册`ScarletEndpointNative`自动SYSTEM服务，不自动启动。先看`native-plan`输出及目标范围，确认后手动`Start-Service ScarletEndpointNative`，或在明确审批后给安装脚本加`-StartService`。
6. 服务心跳注册后，在平台选择实际机器、固定目标和有效期，交另一人员独立批准。只有批准的稳定租约才能执行。`prepared`表示原状态已持久化且等待写入；`configured`表示源端写入阶段；`readback`仅配置相符。只有真实功能证据才能进入`functional_verified`，本包不会自动填写这个结果。

SYSTEM服务只处理机器级配置租约，不读取用户桌面剪贴板。若需要每用户观察，在明确授权的交互用户会话中另用平台执行器的`-mode watch`和独立来源凭据；不要把SYSTEM服务在线等同该用户剪贴板已被观察。源码和既有接入说明提供受控复制/打印/剪贴板命令。

## 恢复与移除

服务保存原配置、计划、实际回读和稳定操作引用；逐目标原值落盘后才写入。撤销/到期触发恢复尝试，离线不会把租约无限延长，恢复回执会留在受保护记录中待回传。Windows原生API可能阻塞，因此不承诺硬实时恢复或物理设备效果。

恢复只比较已记录的真实`applied`凭据。若进程在原生写入与封存实际回读之间崩溃，只有intent/desired不能证明所有权，必须保留冲突并由管理员核对。其他管理员改变目标后也不覆盖。多打印队列没有跨队列原子事务；已封存成功项可单独恢复，未知项保持未知。

以管理员运行`Remove-ScarletEndpoint.ps1`：停止服务、恢复已拥有的原状态，只有恢复成功才移除服务注册。冲突或未完成时会保留注册、原值和证据。脚本不删除程序、DPAPI配置或恢复记录；离线待回传回执可用已安装执行器`-mode native-replay`重传，它不重新执行原生动作。升级/更换来源不自动覆盖已有配置，先完成原租约恢复及组织审计归档流程。

## 实机验收

先在服务停止时运行`Test-ScarletDeployment.ps1 -Mode Plan -OutputPath <测试结果.json>`，只读取匿名能力与权限，不改变原生策略；受保护目录采用跨进程独占锁，运行中的服务不会与验收命令同时操作记录。它的功能结果仍是`not_run`。再按`functional-checklist.csv`由管理员在隔离Windows环境、授权USB/本地测试队列/RDP会话用合成内容逐项验证，保存平台策略/租约/回执和原生观察。不得使用个人文件、真实剪贴板内容或生产打印任务做验收。

每项至少保存：明确目标、基线、采用策略和有效期、准备/配置/回读、实际功能观察、覆盖缺口、撤销/到期恢复和冲突反例。未完成的项保持`not_run`/`unknown`，不填写`passed`。报告应明确原生控制范围，不把一个设备、队列或会话的结果推导为全终端覆盖。
